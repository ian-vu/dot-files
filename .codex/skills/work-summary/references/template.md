# Work Summary Template

The frontmatter and `_links:` section are generated by `scripts/make-frontmatter.sh`. Do not write them manually. The content below starts immediately after the `---` separator from the frontmatter output.

## Body Structure

```markdown
# <Title: concise description of the work> - <YYYY-MM-DD>

## Background

Brief context: why this work was needed, what prompted it.

## Summary

2-5 sentence overview of what was accomplished this session. It should be readable standalone, so someone skimming the file can understand the outcome without reading the detail sections.

## 1. <Section heading>

### Finding / Change

Describe what was discovered or done. Include:

- Relevant code paths and line numbers
- SQL queries run, with results if significant
- Commands executed
- Key decisions made
- Created docs
- Data files created or updated

## 2. <Next section>

...

## Key Takeaways

- Important learnings, gotchas, or decisions that should be remembered
- Non-obvious behavior, things that could trip up future work, and permanent changes made

## Next Session Checklist

<!-- Only include this section if there are follow-ups, audits, or planned work.
     Omit the section entirely if nothing is pending. -->

### Audit / Verify

- [ ] <thing to check>

### Planned Work

- [ ] <next concrete task>

### Open Questions

- <unresolved question>
```

## Formatting Rules

- File paths: write every file path as a markdown link, such as `[path/to/file.py](path/to/file.py)`, to support `gf` navigation in Neovim.
- Thoroughness: include significant SQL queries, code snippets, file paths, and command outputs.
- No chatter: omit conversational back-and-forth; include only substantive findings and actions.
